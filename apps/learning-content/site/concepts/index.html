Model

A model is the thing that makes predictions.

In this project, a galaxy model will eventually receive an image and return something like:

{
  "label": "spiral",
  "confidence": 0.82
}

A trained model has two important parts:

architecture
weights

Neural Network

A neural network is a model made from connected layers of small math units.

Those small units are often called:

neurons
nodes
units

The network receives numbers, transforms them through layers, and returns an output.

For a galaxy classifier:

image pixels in
  -> neural network
  -> galaxy label probabilities out

Simple diagram:

Input numbers        Hidden layer        Output

pixel values         learned patterns     class scores

  x1 --------------- h1 --------------- spiral
   \ \             /  |  \             /
  x2 --\---------- h2  |   \--------- elliptical
   \    \        /     |             /
  x3 ----\------ h3 ---|----------- lenticular
          \            |           /
  x4 ------\---------- h4 ------- irregular

In real image models, there are many more inputs, layers, and weights.

Neurons, Network, And Weights

These words are connected, but they are not the same thing.

neuron
  one small math unit

network
  many neurons connected together in layers

weight
  a learned number on a connection between neurons

architecture
  the design of how neurons/layers are arranged

trained model
  architecture + learned weights

Simple picture:

input neuron        hidden neuron        output neuron

    x1 ---- weight ---- h1 ---- weight ---- spiral score
    x2 ---- weight ---- h2 ---- weight ---- elliptical score
    x3 ---- weight ---- h3 ---- weight ---- irregular score

The neurons do the calculations. The weights decide how strongly information moves from one neuron to the next.

Before training:

weights are random
predictions are bad

After training:

weights have been adjusted
predictions become useful

What A Neuron Does

A neuron takes input numbers, multiplies them by weights, adds them together, and produces an output number.

Tiny example:

input_1 * weight_1
input_2 * weight_2
input_3 * weight_3
       +
     bias
       |
       v
 output number

Another way to see it:

inputs       weights       result

  0.8   x     0.5
  0.1   x    -0.2
  0.4   x     0.9
          + bias
          = neuron output

The weights decide which inputs matter more.

Where The Neuron Numbers Come From

In our galaxy classifier, the input numbers come from the galaxy image.

A computer does not see this:

"a spiral galaxy"

It sees pixel numbers.

For a simple grayscale example:

black pixel  = 0.0
gray pixel   = 0.5
white pixel  = 1.0

A tiny galaxy image patch could become:

0.1  0.2  0.8
0.0  0.5  1.0
0.1  0.4  0.9

Those numbers can become neuron inputs.

If the image is color, each pixel usually has three numbers:

R = red value
G = green value
B = blue value

Example color pixel:

R = 0.2
G = 0.4
B = 0.9

So a color galaxy image is not one brightness number per pixel. It is usually:

height x width x 3 color channels

For learning the concept, grayscale brightness is simpler. For real image models, RGB color channels are common.

Concrete first-layer example:

input_1 = 0.1  from one pixel
input_2 = 0.2  from another pixel
input_3 = 0.8  from another pixel

Then the neuron uses weights:

weight_1 = 0.5
weight_2 = -0.2
weight_3 = 1.0
bias     = 0.1

Calculation:

0.1 * 0.5   = 0.05
0.2 * -0.2  = -0.04
0.8 * 1.0   = 0.80
bias        = 0.10
------------------
output      = 0.91

So in this case:

inputs  = pixel brightness numbers from the image
weights = learned importance numbers inside the model
bias    = learned adjustment number
output  = one new number passed to the next layer

In later layers, the inputs are no longer raw pixels. They are pattern signals from previous neurons.

Later-layer example:

input_1 = edge_strength
input_2 = curve_strength
input_3 = bright_center_strength

For a galaxy image, those could have values:

edge_strength          = 0.7
curve_strength         = 0.9
bright_center_strength = 0.8

A neuron might combine them like this:

0.7 * 0.4
0.9 * 1.2
0.8 * 0.3
+ 0.1 bias
= 1.7

That output could mean:

"this part of the network sees strong spiral-like evidence"

Neuron Example With Simple Numbers

Think of one neuron as a tiny calculator.

It does this:

input_1 * weight_1
+ input_2 * weight_2
+ input_3 * weight_3
+ bias
= output

Example:

input_1 = 2
input_2 = 5
input_3 = 1

weight_1 = 0.5
weight_2 = 0.2
weight_3 = -1.0

bias = 0.1

Now calculate:

2 * 0.5   = 1.0
5 * 0.2   = 1.0
1 * -1.0  = -1.0
bias      = 0.1
----------------
output    = 1.1

So this neuron outputs:

1.1

That is all a neuron is at the basic level: a small calculator with numbers.

Galaxy Neuron Example

Imagine we describe a galaxy image with three simple features:

bright_center = 0.8
has_arms      = 0.9
is_round      = 0.2

A neuron that tries to detect "spiral-like" patterns might use weights like:

bright_center weight = 0.4
has_arms weight      = 1.2
is_round weight      = -0.5
bias                 = 0.1

Calculation:

0.8 * 0.4   = 0.32
0.9 * 1.2   = 1.08
0.2 * -0.5  = -0.10
bias        = 0.10
------------------
output      = 1.40

This neuron gives a high output because has_arms is high and has a strong positive weight.

That means this neuron is acting like:

"I see evidence for a spiral-like pattern."

Important: real neural networks do not start with human-written meanings like this. During training, the model learns useful weights from many examples.

Network Example With Multiple Neurons

A network is many neurons connected together.

The important idea:

the output of one layer becomes the input to the next layer

So yes, in a way, one neuron's output can feed into another neuron.

Tiny network:

Input layer          Hidden layer           Output layer

brightness --------> hidden_neuron_1 ----\
arms_score --------> hidden_neuron_2 ------> spiral_score
roundness ---------> hidden_neuron_3 ----/

Example input values:

brightness = 0.8
arms_score = 0.9
roundness  = 0.2

First hidden neuron:

hidden_neuron_1 =
  0.8 * 0.5
+ 0.9 * 1.0
+ 0.2 * -0.2
+ 0.1 bias
= 1.36

Second hidden neuron:

hidden_neuron_2 =
  0.8 * -0.3
+ 0.9 * 0.4
+ 0.2 * 1.2
+ 0.0 bias
= 0.36

Third hidden neuron:

hidden_neuron_3 =
  0.8 * 0.2
+ 0.9 * -0.1
+ 0.2 * 0.7
+ 0.2 bias
= 0.41

Now the output layer uses those hidden neuron outputs as its inputs:

spiral_score =
  hidden_neuron_1 * 1.1
+ hidden_neuron_2 * 0.3
+ hidden_neuron_3 * -0.4
+ 0.0 bias

Put in the numbers:

spiral_score =
  1.36 * 1.1
+ 0.36 * 0.3
+ 0.41 * -0.4
+ 0.0
= 1.44

So the full flow is:

raw inputs
  |
  v
hidden neurons calculate pattern numbers
  |
  v
output neurons calculate class scores

This is the key network idea:

neurons do not work alone
layers of neurons pass numbers forward through the network

Where Weights Exist Between Neurons

Weights live on the connections into a neuron.

This means:

previous layer output -- weight --> next layer neuron

The previous layer output is a number.

The connection weight is another number.

The next neuron multiplies them:

previous_output * connection_weight

Then the next neuron adds many of these together.

Example:

Layer 1 outputs:
  neuron_A_output = 0.91
  neuron_B_output = 1.40
  neuron_C_output = 0.20

Layer 2 neuron receives all three:
  0.91 * weight_from_A
+ 1.40 * weight_from_B
+ 0.20 * weight_from_C
+ bias
= layer_2_neuron_output

With numbers:

0.91 * 0.5  = 0.455
1.40 * 0.9  = 1.260
0.20 * -0.3 = -0.060
bias        = 0.100
-------------------
output      = 1.755

So both statements are true:

a neuron does inputs * weights + bias
weights are on the connections into that neuron

The connection is not separate from the neuron math. The connection weight is one of the weights used inside the next neuron's calculation.

Another way to say it:

previous neuron output becomes next neuron input
the connection between them has a weight
the next neuron multiplies that input by that connection weight

Hidden Neurons

Hidden neurons are neurons inside the network that are not the original input and not the final output.

They are called hidden because we do not directly give them labels like:

this neuron is definitely spiral arms
this neuron is definitely galaxy center

Instead, hidden neurons calculate intermediate numbers.

Simple idea:

input neurons
  raw image numbers

hidden neurons
  intermediate calculations learned by the model

output neurons
  final class scores

Diagram:

pixels
  |
  v
hidden layer 1
  |
  v
hidden layer 2
  |
  v
hidden layer 3
  |
  v
class scores

The hidden neurons are already calculated values:

inputs * weights + bias = hidden neuron output

That hidden neuron output then becomes input to the next layer.

That means:

previous neuron output = next layer input_n

Example:

hidden_neuron_A output = 6.5

In the next layer, another neuron may treat that as:

input_1 = 6.5

Then that next neuron has its own weight for that input:

6.5 * next_layer_weight_1

So the previous output is the next input. The next layer weight is a separate learned number.

So the flow is:

pixel values
  |
  v
hidden neuron outputs
  |
  v
more hidden neuron outputs
  |
  v
final prediction

Hidden Does Not Mean Magic

Hidden does not mean unknowable magic.

It means:

the neuron is inside the network
we did not manually name exactly what it means
it learned a useful intermediate calculation during training

Sometimes we can inspect hidden layers and see that they respond to things like:

edges
curves
textures
bright centers
spiral-like shapes

But the model did not receive a label for every hidden neuron.

The model only receives the final training label:

this image is spiral
this image is elliptical
this image is irregular

The hidden neurons organize themselves because changing their weights helps reduce prediction mistakes.

CNN Filter Weights And Pixel Importance

Your intuition is close:

a bigger weight can make one incoming signal matter more to the next calculation

For one normal neuron:

previous_neuron_output = 0.8
old weight = 0.20
old signal = 0.8 * 0.20 = 0.16

new weight = 0.23
new signal = 0.8 * 0.23 = 0.184

Because the input is positive, the larger positive weight sends a larger positive signal to the next neuron.

CNN nuance:

the first CNN input is RGB pixel numbers
one pixel usually has 3 numbers: R, G, B
the learnable weights are inside convolution filters
a filter looks at a small local patch, not only one pixel

Example first CNN filter:

input patch shape = 3 x 3 x 3
3 rows
3 columns
3 RGB channels

filter weights shape = 3 x 3 x 3
one learned weight for each patch position and color channel

So the first convolution calculation is roughly:

sum(pixel_value * filter_weight) + bias

That produces one activation value in a feature map.

Important:

CNN does not usually learn "this exact image pixel is always important"
CNN learns filters that can detect useful local patterns across the image

For a galaxy image, a learned filter might become sensitive to:

bright center contrast
edge-like brightness changes
curved/arc-like local texture
color/brightness pattern in a local patch

The same filter slides across many image positions. This is called weight sharing.

That means:

if an edge-like pattern matters on the left side,
the same filter can also detect a similar pattern on the right side

During training, backpropagation calculates gradients for many weights:

filter weight A: move up a little
filter weight B: move down a lot
filter weight C: almost unchanged
classifier weight D: move up
classifier weight E: move down

So the CNN does not get one global "make all spiral pixels important" command.

It gets many small weight updates that slowly make useful pattern detectors and class scores better.

How The Weights Change

The training loop is:

1. start with random weights
2. pass an image through the network
3. produce a prediction
4. compare prediction with the correct label
5. calculate loss/error
6. update weights a little
7. repeat for many images

Example:

image: galaxy_001.jpg
correct label: spiral

model prediction:
spiral:     0.20
elliptical: 0.70
irregular:  0.10

The prediction is wrong.

Training asks:

which weight changes would make spiral score higher
and elliptical score lower for this example?

Then it nudges many weights a tiny amount.

This process is called:

backpropagation + gradient descent

Plain meaning:

backpropagation
  figures out which weights contributed to the error

gradient descent
  changes those weights slightly to reduce the error

After many labeled images, the network becomes better at turning pixels into class predictions.

The model does not predict its own weights as the final answer.

More precise:

model predicts the class
training algorithm updates the weights

Example:

model prediction:
spiral:     0.20
elliptical: 0.70

training algorithm:
changes weights so future predictions move closer to the correct label

Logits, Probabilities, And Loss

Logits are raw output scores before probabilities.

Example:

elliptical: 0.20
spiral:     0.35
lenticular: 0.10
irregular:  0.15

They are not probabilities yet.

That means logits do not need to:

be between 0 and 1
add up to 1
look like percentages

A model can output logits like:

[-2.0, 0.5, 3.0, 1.2]

Those are just raw class scores. Higher usually means "the model currently favors this class more."

Softmax converts logits into probabilities that add up to about 1.0.

Example:

elliptical: 0.25
spiral:     0.29
lenticular: 0.22
irregular:  0.24

Softmax With Simple Numbers

Softmax does three ideas:

1. turn each raw score into a positive number
2. add all positive numbers together
3. divide each positive number by the total

Tiny simplified example:

logits:
elliptical = 1
spiral     = 2
irregular  = 3

Softmax first uses e^score.

You do not need to deeply know e yet. For now, read it as:

make bigger scores grow much more than smaller scores

Approximate values:

e^1 = 2.72
e^2 = 7.39
e^3 = 20.09

Add them:

2.72 + 7.39 + 20.09 = 30.20

Divide each by the total:

elliptical = 2.72  / 30.20 = 0.09
spiral     = 7.39  / 30.20 = 0.24
irregular  = 20.09 / 30.20 = 0.67

Now they are probabilities:

0.09 + 0.24 + 0.67 = 1.00

So softmax turns:

raw scores

into:

probability-like class confidence values

Why The Code Subtracts The Biggest Logit

In softmax(), the code does:

max_logit = max(logits)
exp_values = [math.exp(logit - max_logit) for logit in logits]

This is only for numerical stability.

It does not change the final probabilities in a meaningful way.

Example:

logits = [1, 2, 3]
max_logit = 3
logits after subtracting max = [-2, -1, 0]

Softmax of [1, 2, 3] and softmax of [-2, -1, 0] gives the same probability pattern.

The reason is practical:

e^1000 is too huge for normal computer numbers
e^(1000 - 1000) is safe

Loss is a number that says how wrong the prediction is compared with the known correct label.

For our tiny example:

correct label from manifest = spiral
spiral probability = 0.29
loss = higher than if spiral probability was 0.90

Cross-Entropy Loss With Simple Numbers

Cross-entropy loss looks at the probability assigned to the correct class.

In our case:

correct class = spiral

If the model gives spiral a high probability:

spiral probability = 0.90
loss = small

If the model gives spiral a low probability:

spiral probability = 0.10
loss = large

The formula used by cross_entropy_loss() is:

loss = -log(correct_class_probability)

You do not need to master logarithms yet. The important behavior is:

probability close to 1.0 -> low loss
probability close to 0.0 -> high loss

Examples:

correct probability = 0.90
loss = -log(0.90) = 0.105

correct probability = 0.50
loss = -log(0.50) = 0.693

correct probability = 0.10
loss = -log(0.10) = 2.303

So lower loss means:

the model put more probability on the correct answer

Higher loss means:

the model did not believe the correct answer enough

In real training, the model uses loss to update weights.

In the current skeleton:

loss is calculated
weights are not updated

So it is useful for understanding the training shape, but it is not learning yet.

A forward pass means:

More concretely:

image numbers + current model weights -> logits

The forward pass does not transform weights into logits.

In code:

logits = active_model(torch_image)

means:

take this image tensor

use the model's current weights inside those layers
produce raw class scores called logits

weights are used
logits are produced
weights are not updated yet

input tensor
  -> model layers
  -> logits
  -> loss
  -> backpropagation
  -> optimizer updates weights

optimizer.step() -> updated weights

old weight = 0.2
new weight = 0.25

Then the next forward pass uses the new weight:

0.5 * 0.25 = 0.125 output signal

So "weights updated" means:

the internal numbers inside the model changed

and the next forward pass can produce different logits and probabilities.

What Gradient Means

A gradient is a direction-and-size number for a weight.

It answers:

if this weight changes a little,
does the loss go up or down?
and by how much?

Another way to say it:

gradient = how this weight should move to reduce the loss

For our case:

correct label = spiral
loss is high if spiral probability is too low
gradient tells each weight how it contributed to that loss

Tiny update example:

current weight = 0.20
gradient = -0.30
learning_rate = 0.10

SGD updates roughly like this:

new_weight = current_weight - learning_rate * gradient
new_weight = 0.20 - 0.10 * -0.30
new_weight = 0.23

Because the gradient was negative, subtracting it made the weight go up.

If the gradient was positive:

current weight = 0.20
gradient = 0.30
learning_rate = 0.10

new_weight = 0.20 - 0.10 * 0.30
new_weight = 0.17

So with SGD:

negative gradient -> weight goes up
positive gradient -> weight goes down
bigger gradient -> bigger update
smaller gradient -> smaller update

Important nuance:

high loss often creates stronger pressure to change weights
but high loss does not mean every weight goes up
high loss also does not automatically mean every gradient is big
each weight has its own gradient
some weights go up
some weights go down
some barely change

Why:

loss = how wrong the current prediction was
gradient = how one specific weight affected that wrongness

So one high-loss prediction can produce different gradient sizes:

large gradient for weights that strongly caused the mistake
small gradient for weights that barely affected this prediction
near-zero gradient for weights blocked by the current path

In a tiny one-neuron example, high loss often means a bigger gradient:

gradient = 2 * error * input

But in a real neural network, the input path, activation functions, and later layers also affect the gradient.

The goal is not:

make weights lower

The goal is:

move each weight in the direction that should make future loss lower

So gradient tracking means PyTorch remembers the forward-pass math so it can later calculate those direction numbers.

That is why the forward-only proof uses:

torch.no_grad()

and the training step does not. Training needs gradients.

Concrete Gradient Calculation Example

This is a tiny math example, smaller than a CNN, so the direction is visible.

Imagine one input, one weight, and one target:

input x = 2
weight w = 0.5
target = 4

Forward calculation:

prediction = x * w
prediction = 2 * 0.5
prediction = 1

Error:

error = prediction - target
error = 1 - 4
error = -3

Simple squared loss:

loss = error * error
loss = -3 * -3
loss = 9

For this simple formula, the gradient is:

gradient = 2 * error * input
gradient = 2 * -3 * 2
gradient = -12

Why does the input appear in the gradient?

prediction = input * weight

If the input is bigger, changing the weight has a bigger effect on the prediction.

SGD update:

new_weight = old_weight - learning_rate * gradient
new_weight = 0.5 - 0.1 * -12
new_weight = 1.7

The gradient is negative, so the weight goes up.

New prediction:

new_prediction = 2 * 1.7
new_prediction = 3.4

That is closer to target 4, so loss went down.

In the CNN, PyTorch does this same idea through many layers:

pixels
  -> CNN weights
  -> logits
  -> loss
  -> gradients for many weights
  -> optimizer updates weights

The formulas are bigger, but the question is the same:

if this weight changes a little, what happens to loss?

What Backpropagation Means

Backpropagation is the step where PyTorch calculates gradients through the network.

In code:

loss_before_tensor.backward()

Conceptually:

loss
  -> classifier weights
  -> feature layers
  -> earlier CNN weights

It works backward from the final loss to each trainable weight.

Forward pass:

input image
  -> current weights
  -> neuron outputs
  -> logits
  -> loss

Backward pass:

loss
  -> how much did each logit affect loss?
  -> how much did each neuron output affect that logit?
  -> how much did each weight affect that neuron output?

Tiny math example:

input x = 0.5
weight w = 0.2

forward:
output = x * w
output = 0.5 * 0.2
output = 0.1

If the loss says:

output should be higher

then backpropagation can see:

increasing w will increase output

because:

output = x * w

and x is positive.

So the gradient tells the optimizer:

move w upward

Backpropagation does not update weights by itself. It only calculates the gradients.

Gradient And Backpropagation Logic Flow

The whole training update can be read as a logic pipeline:

1. input data
   image pixels already normalized into tensor values

2. forward pass
   current weights transform image tensor into logits

3. loss
   logits are compared with the known correct label

4. backward pass
   PyTorch calculates gradients for trainable weights

5. optimizer step
   optimizer changes weights using gradients and learning rate

6. next forward pass
   same image can now produce different logits/probabilities

The weight update rule for simple SGD is:

new_weight = old_weight - learning_rate * gradient

So:

gradient positive -> weight moves down
gradient negative -> weight moves up
larger absolute gradient -> larger weight move

Important:

high loss does not automatically mean lower gradient
high loss does not automatically mean higher gradient for every weight
gradient size depends on how much that specific weight affected this prediction

If a positive input connection has a negative gradient:

old weight = 0.20
gradient = -0.30
learning_rate = 0.10
new weight = 0.23

That usually means this connection can push more strongly on the next neuron during the next forward pass.

If the connection is negative, "stronger" needs more care. The weight can become less negative, more negative, or closer to zero. The optimizer is trying to make future loss lower, not simply make every connection bigger.

But the model has many weights, so the update is not one global action.

It is more like:

weight A: move up a little
weight B: move down a lot
weight C: almost unchanged

Checkpoint Preprocessing Contract

A checkpoint needs both learned weights and the recipe for preparing its input. The recipe is configuration we choose, not another weight learned by backpropagation. M49 prevents training and serving from silently using different pixel preparation (often called training-serving skew).

Why The Recipe Matters

The CNN accepts several image sizes because it uses adaptive pooling. That does not mean changing size preserves its prediction: resizing changes pixels, neighborhoods and the features the filters detect. Previously the CLI could resize while the API kept the original size. The same weights could therefore receive different numbers.

This contract has one supported recipe: RGB channels, optional exact-size bilinear resize, then divide channel values by 255. It records a version so unsupported future recipes are rejected instead of interpreted as today's recipe. It does not record software versions or guarantee bit-for-bit equality across every future library/platform version.

Reading The CNN Diagram From Pixels To Classes

Start here before reading the weight matrices. The main distinction is input pixels vs internal features vs output classes. They are different kinds of numbers, even when two lists happen to have the same length.

Prefer the green-input/purple-output neuron pictures? Start with two weighted-sum diagrams: RGB first, pooled features later and their explanation.

ONE artificial RGB image: 3x3 pixels, each pixel has R, G and B
  -> FOUR convolution filters examine that SAME image
  -> FOUR 3x3 response maps
  -> ReLU keeps positive responses, replaces negative responses with zero
  -> average each map separately: FOUR pooled feature values
  -> classifier uses its 4x4 WEIGHT matrix and 4 biases
  -> FOUR raw class scores (logits)
  -> softmax: FOUR class probabilities

The final prediction is a list of four scores/probabilities, not a 3x3 matrix. Later sections of the diagram zoom back into earlier filters to explain their weights; they are not extra layers added after the final classifier.

RGB Is Multiplied First, Features Are Multiplied Later

Yes, RGB values are multiplied by learned weights. That happens in the convolution, before the final classifier matrix. Our CNN has two different sets of weights doing different jobs:

RGB numbers x CONVOLUTION weights + convolution bias
    -> response maps -> ReLU -> average pooling
    -> four feature values a[0], a[1], a[2], a[3]

feature values x CLASSIFIER weights + classifier bias
    -> four logits -> softmax probabilities

The final features are calculated FROM the RGB data. The image information is still involved, but it has been transformed and summarized. The classifier does not receive the original 27 RGB channel numbers again.

First multiplication: an actual RGB value and a convolution weight. For image A, filter 0, center window, red center pixel:

RGB input x       = 180 / 255 = 0.705882370
Convolution weight k         = -0.102860123
One contribution x * k      = -0.072607145

That is one of 27 products in this window: nine red, nine green, nine blue. Add all 27 products and the filter bias to get center response 0.037116095. This is one intermediate response, not a galaxy logit and not yet pooled feature a[0]. Repeating the filter at nine image positions, applying ReLU, and averaging gives a[0] = 0.020664100. Other filters produce a[1], a[2], and a[3].

The first panel of the simpler neuron drawing shows all 27 channel values and their 27 filter-0 weights for this center window. The purple dot is explicitly an intermediate convolution response. Color identifies a calculated output, not necessarily a class: read each dot's label.

Second multiplication: an actual feature value and a classifier weight. For the connection from feature 1 to the spiral score:

Feature input a[1]       =  0.279412299
Classifier weight W[1,1] = -0.234996617
One contribution        = -0.065660946

Where did -0.234996617 come from? It is one parameter in classifier.weight. PyTorch randomly initialized it when this fresh model was created; seed 7 makes that starting value reproducible for this observation. It was not calculated from feature 1, and it does not by itself mean a probability or final "importance." During training, SGD changes it from this initial value using its gradient.

The product -0.065660946 is only one addend inside the spiral logit. It is not the next image input, not a new feature, not a probability, and not the complete spiral logit:

spiral logit
  = a[0]*W[spiral,0]
  + a[1]*W[spiral,1]       <- highlighted term = -0.065661
  + a[2]*W[spiral,2]
  + a[3]*W[spiral,3]
  + b[spiral]

  = -0.005528 - 0.065661 - 0.023923 + 0.007959 + 0.197863
  = approximately 0.110709

This is not 0.705882370 * W[1,1]: that RGB value belonged to the earlier convolution stage. The four partial products meet at the spiral output and are summed once with its bias. Softmax then compares this complete spiral logit with the other three complete logits to give spiral probability 0.294906646.

The two inputs in these examples differ because they are at different places in the network. A weight always multiplies the incoming activation at its own connection: early activations can be pixel channel values, while later activations are calculated features.

Both Calculations Can Be Written As Matrices

For one RGB window, arrange its 27 channel values into a vector. Arrange each complete filter's 27 weights into a row:

Convolution, ONE window:
  filter weights (4x27) @ RGB patch (27,) + filter biases (4,)
  = four responses at that window position

Repeat at all nine positions, then ReLU and average each map:
  four feature values a, shape (4,)

Classifier, ONE image:
  classifier weights (4x4) @ features a (4,) + class biases (4,)
  = four logits

This is a mathematical view of the existing Conv2d, not a replacement implementation. The classifier's 4x4 matrix cannot multiply the raw 27-value image vector directly: it expects four feature inputs. The filter weights are reused across windows; the classifier weights are a separate parameter tensor. See RGB slices and windows and the four-feature dot product.

The Optimizer Changes Both Sets Of Weights

The forward-pass multiplications calculate responses and logits. They do not change weights. Backward calculates each weight's own gradient. Then our plain SGD optimizer applies:

change = -learning_rate * gradient
new_weight = old_weight + change
           = old_weight - learning_rate * gradient

So we do not simply "add the gradient." We add a change pointing opposite the gradient. With learning rate 0.1, the same first optimizer step produces:

Connection Before Its gradient After optimizer
Convolution: filter 0, red center -0.102860123 +0.014876489 -0.104347773
Classifier: feature 1 to spiral -0.234996617 -0.061517961 -0.228844821

The positive-gradient weight decreases; the negative-gradient weight increases. Both updates are part of the same learning step, not two different learning rules. The saved RGB inputs stay unchanged. The next forward pass recalculates features from the updated filters: for example image A's a[1] changes from 0.279412 to 0.261860 after update 1. The new classifier weights then use those new feature values. See why gradients differ by connection.

Whole Tiny CNN Training Cycle

The current tiny training run is one repeated cycle, not two unrelated ways of learning. It has two groups of trainable parameters at different depths:

stored RGB pixels (data; never changed by training)
  -> convolution filter weights + biases (trainable)
  -> ReLU (calculation; no weights)
  -> average pooling (calculation; no weights)
  -> four pooled features (temporary results, recalculated every forward pass)
  -> classifier weights + biases (trainable)
  -> four logits
  -> CrossEntropyLoss compares logits with labels
  -> backward calculates a separate gradient for every trainable parameter
  -> SGD changes convolution parameters AND classifier parameters
  -> next forward pass uses the same RGB pixels with the updated parameters

The weights are not supplied as a new random input on every pass. create_tiny_galaxy_cnn() initializes them once (repeatably under seed 7), and run_torch_training_loop() keeps that same model and SGD optimizer for every epoch. The first forward pass uses the initial parameters. Every later forward pass uses the parameter values left by the preceding optimizer.step().

For the observed two-image batch, one epoch contains one optimizer update. Two epochs therefore produce this sequence:

Moment Conv filter 0, red-center weight Feature 1 to spiral weight Image A feature 1 Image A spiral probability Same-batch loss
Before update 1 -0.102860 -0.234997 0.279412 0.294907 1.457183

After update 2 -0.105621 -0.223311 0.246251 0.311672 1.387335

Those changing feature values are not stored replacements for the pixels. They are fresh intermediate results. Updated convolution filters examine the unchanged RGB batch and calculate different response maps; ReLU and pooling then summarize those maps again. Updated classifier parameters turn the newly calculated features into new logits.

Backward and the optimizer also have separate jobs:

loss.backward()     -> fills each parameter's .grad; parameter values stay fixed
optimizer.step()    -> applies new = old - learning_rate * gradient

For update 1, the example convolution gradient is +0.014876, so SGD decreases that weight. The example classifier gradient is -0.061518, so SGD increases that weight (makes it less negative). During update 2, the model starts from those updated values and calculates new gradients, +0.012733 and -0.055341, from the new forward pass. A high loss does not imply every gradient is large or has the same sign; each gradient measures the local sensitivity of loss to its own parameter.

Three By Three And Four By Four Have Different Jobs

"Matrix" only means a rectangular arrangement of numbers. Always ask what its rows, columns and entries represent:

Object Rows/columns mean What each entry is Does training update its entries directly?
3x3 image channel Vertical/horizontal pixel position An input channel value No
3x3 kernel slice Vertical/horizontal offset within a filter window A learned weight Yes, using gradients
3x3 feature map in this tiny run Vertical/horizontal image position A computed response No; recalculated from image and weights
4x4 classifier matrix W Row = class; column = pooled feature A learned connection weight Yes, using gradients
4x4 classifier gradient matrix Same class/feature indexing as W Loss sensitivity for that weight Recalculated by backward, then used by SGD
Four-element output vector One entry per class Logit or, after softmax, probability Computed from the features, weights and biases

Why 4x4? We chose four filters, so pooling produces four inputs to the classifier. We have four target classes, so the classifier needs four outputs. Each of four outputs receives four inputs: 4 x 4 = 16 connection weights, plus four biases outside that matrix. The two fours have different reasons. With eight filters and four classes, the classifier weight matrix would be 4x8; that is an explanation, not a proposed architecture change.

Why 3x3? The filter window is three pixels high and wide. The fixture image is also 3x3, a separate choice. Padding keeps these tiny response maps 3x3. A bigger image can still use 3x3 filters; the filter size is not determined by the number of classes.

W0, W1 and W2 in the diagram are snapshots of the same classifier matrix before updates, after update 1, and after update 2. They are not three different layers or different classes.

Kernel Slices And The Center Convolution

A kernel/filter is a small set of learned weights used to combine a local patch of image values. Our RGB filter needs three 3x3 grids: one for red, one for green, one for blue. Each grid is a kernel slice, not a separate galaxy image. One complete filter therefore has 3 x 3 x 3 = 27 weights and one bias. Four filters contain 12 such slices.

Where The Three RGB Planes Come From

The PPM file writes three values for each pixel as (R,G,B) triplets. Separating the first, second, and third value of every triplet gives three planes for the same image:

Original RED values          Original GREEN values        Original BLUE values
[   0   64  255 ]            [   0   64  255 ]            [   0   64  255 ]
[  32  180  255 ]            [  32  180  240 ]            [  96  220  200 ]
[   0   80  220 ]            [   0   80  220 ]            [  20  160  255 ]

These are not three images and they are not columns being added. They are three measurements at every pixel position. PyTorch receives them in channel-first CHW order: red plane, green plane, blue plane. Dividing each entry by 255 gives the normalized planes used below. For example, the center location is:

red[1,1]   = 180/255 = 0.705882
green[1,1] = 180/255 = 0.705882
blue[1,1]  = 220/255 = 0.862745

Sliding To Nine Positions, ReLU, And Pooling

The same 27 filter weights and same bias are reused at every output position. Moving the 3x3 window changes which image values line up with those weights.

Why Changing The Output Row Changes The Input Rows

The dropdown labeled Output row selects a row in the response map, not a row to copy directly from the input. With kernel_size=3 and padding=1, the mapping is:

input row    = output row + kernel row - 1
input column = output column + kernel column - 1

The filter keeps the same three kernel rows and columns. The output position tells us where to place that fixed 3x3 window on the padded image:

selected output (1,0)     selected output (2,0)

input rows:    0, 1, 2    input rows:    1, 2, 3
input columns: -1, 0, 1   input columns: -1, 0, 1

                  same filter 0 weights
                  same bias
                  different input-to-weight alignment

For (1,0), kernel row 0 is paired with image row 0, kernel row 1 with image row 1, and kernel row 2 with image row 2. For (2,0), the whole window has moved down one image row: kernel row 0 is paired with image row 1, kernel row 1 with image row 2, and kernel row 2 with padded image row 3. Column -1 is padding in both positions because the output column is the left edge. Coordinates outside the real 0..2 image range are treated as zero.

That is why the same red kernel weight can multiply different pixels at different output rows. For example, the red kernel weight at offset (0,2) is reused unchanged:

output (1,0): red kernel (0,2) x input red (0,1)
output (2,0): red kernel (0,2) x input red (1,1)

The filter has not learned a new value between these two calculations. It has simply slid down one position. Since input red (0,1) and input red (1,1) are different numbers, their products and the final sums are different. The nine response-map cells are therefore nine different sums made with the same 27 weights, not nine copies of one sum.

Why Every Weight Has Its Own Gradient

A gradient entry asks: if this one parameter increased a tiny amount, with the other parameters fixed, how would the loss respond locally? Different parameters affect different weighted sums and paths, so they have separate derivatives. Some values can coincide or be zero; there is not one shared gradient number for the entire model.

For our final linear layer and mean cross entropy, the chain rule gives:

Loss response to class i's logit, for one image: p[i] - target[i]
Class i's logit response to its weight W[i,j]:   a[j]
Multiply these sensitivities:                  (p[i] - target[i]) * a[j]
Average over the batch:                        gradient of mean loss w.r.t. W[i,j]

Why multiply by a[j]? This weight contributes W[i,j] * a[j] to that class score. Holding the feature fixed, increasing the weight by a tiny epsilon changes the score by epsilon * a[j]. Chain rule connects that score change to the resulting loss change. PyTorch calculates this using autograd, not by randomly trying bigger/smaller weights until one works.

For the pictured connection:

image A: (0.294907 - 1) * 0.279412 = -0.197012
image B: (0.295825 - 0) * 0.250066 = +0.073976
batch gradient = (-0.197012 + 0.073976) / 2 = -0.061518

SGD: new weight = -0.234996617 - 0.1 * (-0.061517961)
                = -0.228844821

The negative gradient indicates that a small increase of this weight is a local downhill direction for this batch. SGD therefore increases it, making this negative connection less suppressive for a positive feature. The full loss can still behave differently after large or simultaneous changes; this is a local sensitivity, not an unconditional promise.

Each entry of the 4x4 gradient matrix uses its own class index i and feature index j. Matrix Multiplication Is Many Weighted Sums

W[i,j] means the weight from pooled feature j into class logit i. It is a connection, not the feature/neuron itself. b[i] is an offset added even when every incoming activation is zero.

For one image, using column-vector notation like the video:

z = W @ a + b
(4,) = (4,4) @ (4,) + (4,)
z[i] = sum(W[i,j] * a[j] for j in range(4)) + b[i]

The @ sign is matrix multiplication, not element-by-element multiplication. It repeats one dot product (multiply matching entries and add them) for every row/class. Our final layer produces raw logits: it does not apply the video's sigmoid. ReLU was earlier; softmax is separate for reporting, while CrossEntropyLoss takes logits directly. Review sigma notation and the activation functions.

PyTorch stores a batch of activations as rows, so the same operation is written Z = A @ W.T + b. Here A is (2,4), W is (4,4), and Z is (2,4). Transpose W.T swaps rows and columns so each image's row multiplies each class's weight row. Bias is added to every image row. Numerical matrices and a complete spiral-logit calculation are in the observed run.

What Backward Calculates For This Matrix

For mean cross entropy with ordinary class labels:

E[n,i] = (probability[n,i] - one_hot_label[n,i]) / batch_size
gradient_W = E.T @ A
gradient_b = sum(E over the images)
gradient_A = E @ W

one_hot_label is 1 at the correct class and 0 elsewhere. E tells us how loss responds to each logit, not just whether the winning class was correct. Dividing by batch size matches our mean batch loss. This formula is specific to our softmax/cross-entropy setup; "gradient = error * input" is not a complete formula for every layer or loss.

Sigma, Sigmoid, And ReLU

An activation function transforms a neuron's weighted sum before passing the result onward. Sigmoid and ReLU are two different choices; neither is a weight or an optimizer. Our CNN uses ReLU after convolution, not sigmoid. These notes explain the notation from your video and calculate both functions on our recorded values without changing the model.

"Weighted sum" means: take several incoming numbers, multiply each by its own connection weight, add those products and a bias. "Passing onward" means the resulting number becomes input to the next operation, not that a pixel or class is moved to another neuron. In our convolution, one position combines 27 RGB values this way. At the center its sum is +0.037116, so ReLU passes +0.037116 into the map; at the top-left the sum is -0.101113, so ReLU puts 0 there. Average pooling consumes these map values next. See all contributions and the center calculation.

Reading Sigma And Sum Notation

Lowercase sigma, σ, is a Greek letter used as a function name. In the pictured σ(Wa + b) explanation it denotes sigmoid. Some authors use sigma for an activation function more generally, so always check its definition. ReLU can occupy the activation position in a network, but it has a different formula.

Uppercase sigma, Σ, means "add these terms together". It does not mean sigmoid or ReLU:

z[i] = Σ over j of W[i,j] * a[j] + b[i]
     = W[i,0]*a[0] + W[i,1]*a[1] + ... + b[i]

Video: weighted sum z -> activation σ(z) -> next signal
Ours:  convolution weighted sum z -> ReLU(z) -> pooling

In the first line, the bias is added once, after summing the products. W @ a is matrix notation for computing these weighted sums for all output units. σ is not another learned matrix; σ(z) means apply the named function to each value in z.

Sigmoid Activation

The formula is sigmoid(z) = σ(z) = 1 / (1 + exp(-z)). Here exp(-z) means e raised to -z, with e approximately 2.71828. It acts on each tensor value separately and preserves the tensor's shape. PyTorch sigmoid definition.

For finite real inputs, its mathematical output is between 0 and 1. sigmoid(0) = 0.5; positive inputs give more than 0.5, negative inputs give less. Large positive/negative inputs approach 1/0. Floating-point calculations can round to those endpoints.

This is an S-shaped squashing function. A hidden-layer output of 0.509278 is an activation, not automatically "50.9% probability of spiral". Probability interpretation depends on the output layer, task and loss. Our four-class output uses softmax instead; see the distinction below.

ReLU Activation

ReLU means rectified linear unit: ReLU(z) = max(0, z). Applied independently to each value, it keeps positive values and replaces negative values with zero; zero stays zero. Shape is preserved. PyTorch ReLU definition.

There is no upper cap: for example ReLU(2) = 2, so its outputs are not probabilities. It does not delete a neuron, alter the stored image, or force learned weights to be nonnegative. It transforms the intermediate weighted-sum values produced using those weights.

Our ReLU layer is features[1]; TinyGalaxyCNN.forward() runs:

image -> Conv2d -> ReLU -> average pool -> flatten -> Linear -> logits

The final Linear layer does not have a ReLU after it. Class logits may therefore be negative, and cross entropy can use them normally.

Why Put A Nonlinear Activation Between Layers?

Without a nonlinear activation, consecutive affine transformations can collapse into one:

W2 @ (W1 @ x + b1) + b2
= (W2 @ W1) @ x + (W2 @ b1 + b2)

Adding more such layers alone does not create the nonlinear behavior we want. ReLU introduces input-dependent gating: a weighted sum can pass for one image and become zero for another. Sigmoid introduces a smooth nonlinear transformation instead. This changes both the forward signals and the derivatives used during learning.

In plain words, ReLU lets the next stage receive a filter's positive response at one location and no response at another. It is not deciding "positive means spiral" or deleting negative learned weights. The classifier still has to combine the resulting features to form class scores. Negative weights remain useful because they can subtract a contribution before ReLU, or lower a final class score in the classifier.

ReLU's positive branch has slope 1, whereas sigmoid's slope becomes small near its saturated ends. That is one reason ReLU is useful in hidden layers. ReLU has a different limitation: its non-positive branch blocks the local gradient. Neither choice guarantees better accuracy; we have not run a trained sigmoid-versus-ReLU model comparison.

Activation Derivatives In Our Backward Pass

The local derivative measures how the activation's output responds to a small change in its input. Backpropagation multiplies the arriving loss gradient by that derivative:

dL/dz = dL/da * da/dz

ReLU slope:    1 when z > 0; 0 when z < 0
At z = 0:      the mathematical kink has no unique derivative; PyTorch uses 0
Sigmoid slope: sigmoid(z) * (1 - sigmoid(z))

At our positive center value, ReLU's local slope is 1. Sigmoid's would be 0.509277940 * (1 - 0.509277940) = 0.249913916. At the negative top-left value, ReLU's slope is 0. A local slope is not yet a weight gradient: upstream loss sensitivity and the rest of the chain matter too.

Measured in the same first-batch backward pass, the loss gradient at pooled feature a[0] for image A is 0.132701233. Average pooling distributes it equally to nine positions:

gradient arriving at each ReLU output = 0.132701233 / 9 = 0.014744582
center, positive z: dL/dz = 0.014744582 * 1 = 0.014744582
top-left, negative z: dL/dz = 0.014744582 * 0 = 0

The batch mean is already included in that incoming gradient; do not divide by two again. Convolution then combines each position's gradient with its input patch to obtain shared-filter weight gradients. A blocked position contributes zero through this path, but the same filter weights can still receive gradients from other positions and images. See the full shared-weight calculation, classifier-to-feature gradients and the later SGD update. No optimizer step is performed while checking these derivatives.

One Shared Convolution Weight: 18 Contributions In This Batch

This is the CNN-specific step that the classifier example does not show. A classifier weight is used once per image. A convolution weight is shared: the same one is used at every output position of that filter's response map.

Take the actual filter-0 red-center weight from update 1:

K = features.0.weight[0,0,1,1] = -0.102860123

The indices mean filter 0, input channel 0 (red), kernel row 1, kernel column 1. It is one of the 108 convolution weights. Because it is the center of the 3x3 kernel, it lines up with the red pixel at the same (row, column) as each 3x3 response-map entry. For a corner or edge kernel weight, the aligned value would sometimes come from the zero-padded border instead.

For one output map entry, convolution has the form:

z[n, filter, row, column]
  = sum over channel/kernel-row/kernel-column of
      padded_input[n, channel, row + kernel-row, column + kernel-column]
      * K[filter, channel, kernel-row, kernel-column]
    + bias[filter]

Backpropagation reverses that local multiplication. For this selected center/red weight, its gradient is:

dL/dK = sum over both images and all 3x3 output positions of
        dL/dz[n, 0, row, column] * red_input[n, row, column]

dL/dz means "how the final loss changes if this particular pre-ReLU convolution response z changes a little." It already includes the later classifier, cross-entropy loss, and the mean-over-two-images rule. For image A, the classifier sends dL/da[0] = +0.132701233 to pooled feature 0. Average pooling sends +0.132701233 / 9 = +0.014744582 to every map position, then ReLU passes it only where that pre-ReLU response was positive.

The same idea applies to all 108 convolution weights. Each has its own aligned inputs and its own accumulated gradient, because its filter/channel/kernel position is different. The four convolution biases also collect one dL/dz contribution from every map position; the 16 classifier weights use the later pooled features instead of image pixels. This is why a CNN can learn many small local-pattern parameters at once without changing the stored RGB image.

Why Weight The Reported Average

Suppose three images form batches of two and one:

first batch:  2 images, mean loss 1.0
last batch:   1 image,  mean loss 3.0

incorrect image average: (1.0 + 3.0) / 2 = 2.0
correct image average:   (2 * 1.0 + 1 * 3.0) / 3 = 1.6667

The last image must not count as much as both images in the first batch combined. The loop accumulates batch_mean_loss * actual_batch_size, then divides by the number of image visits. It keeps the shorter last batch instead of dropping its data.

This changes reporting, not the loss passed into backward() or the SGD update. The training average mixes losses recorded before different updates; it is not the final model's evaluation loss and is not a reliable comparison between different batch-size training schedules on its own.

Dataset Quality: Accepted, Skipped, And Rejected

Milestone 50 protects the training input boundary before we add many real files. It does not change the CNN, logits, loss, gradients, SGD, DataLoader batches, evaluation, or checkpoints. It decides whether each manifest row is trustworthy enough to reach those stages.

Four Different Checks

CSV text
  -> CSV structure: quoting and equal row/header column counts
  -> manifest meaning: required fields, known label/split, unique image_id
  -> image data: path exists, supported extension, readable pixels
  -> preprocessing: RGB shape, pixel range, requested resize
  -> only then can the sample enter Dataset/DataLoader/training

A malformed CSV is rejected before GalaxyManifestRecord objects are created. A valid manifest may still point to a missing, unsupported, or corrupt image, so dataset creation performs another boundary check.

Stage Code Responsibility
Parse and validate validate_manifest() Reports malformed CSV and exact row/field errors without calling .strip() on a missing value.
Preserve source row GalaxyManifestRecord Keeps manifest_row only for diagnostics; it is not a model feature.
Load/preprocess create_dataset_splits() Classifies each record as accepted, intentionally skipped missing, or rejected.
Refuse bad runs GalaxyDatasetQualityError Stops the run while retaining the partial split result and all three counts for inspection/tests.

What The Three Outcomes Mean

Outcome Meaning Does training continue?
accepted The image exists and passes source-file validation; its manifest-backed lazy sample can later be decoded by Dataset access. Yes.
skipped_missing The path did not exist and the caller explicitly allowed missing-file skips. Yes, but the exclusion is counted and named.
rejected The file existed but was corrupt/unsupported/invalid, or strict mode rejected a missing path. No. A GalaxyDatasetQualityError is raised.

skip_missing=True does not mean "ignore every error." It means only this narrow policy:

FileNotFoundError -> record skipped_missing and continue
ValueError/OSError from existing data -> record rejected and fail the run

Why? A deliberately incomplete local sample can still be inspected when some downloads have not arrived. But silently dropping corrupt images could produce apparently successful metrics from a different dataset than the manifest claims.
